# .vault Binary Format Specification — FileVault v2.0

## Overview

The `.vault` file format is a custom binary container that stores encrypted file data along with all metadata needed for decryption (except the password). The format is designed for:

- **Self-contained decryption** — all parameters stored in-file
- **Authentication** — tamper detection via GCM auth tag
- **Versioning** — future format upgrades without breaking compatibility
- **Portability** — little-endian byte order, no alignment padding

## Binary Layout

```
┌──────────────────────────────────────────────────────────┐
│ FIXED HEADER (20 bytes)                                  │
├──────┬──────┬────────────────────────────────────────────┤
│ Off  │ Size │ Field                                      │
├──────┼──────┼────────────────────────────────────────────┤
│ 0    │ 8    │ Magic bytes: "FVAULT\x00\x00"              │
│ 8    │ 1    │ Format version (0x01)                       │
│ 9    │ 1    │ Algorithm ID (0x01 = AES-256-GCM)           │
│ 10   │ 1    │ KDF ID (0x01 = PBKDF2-HMAC-SHA256)          │
│ 11   │ 1    │ Flags (0x00, reserved)                      │
│ 12   │ 2    │ Salt length (LE uint16, typically 16)        │
│ 14   │ 2    │ Nonce length (LE uint16, typically 12)       │
│ 16   │ 2    │ Tag length (LE uint16, typically 16)         │
│ 18   │ 2    │ Original filename length (LE uint16)         │
├──────┴──────┴────────────────────────────────────────────┤
│ VARIABLE HEADER                                          │
├──────┬──────┬────────────────────────────────────────────┤
│ 20   │ S    │ Salt (S = salt_len bytes)                   │
│ 20+S │ N    │ Nonce/IV (N = nonce_len bytes)              │
│ ...  │ F    │ Original filename (F = name_len, UTF-8)     │
├──────┴──────┴────────────────────────────────────────────┤
│ PAYLOAD                                                  │
├──────┬──────┬────────────────────────────────────────────┤
│ H    │ X    │ Ciphertext (AES-256-GCM encrypted data)     │
│ H+X  │ T    │ Authentication tag (T = tag_len bytes)       │
└──────┴──────┴────────────────────────────────────────────┘

H = 20 + S + N + F (total header size)
X = file_size - H - T  (ciphertext size)
```

## Field Details

### Magic Bytes (8 bytes)
ASCII string `"FVAULT"` followed by two null bytes (`\x00\x00`). Used to identify FileVault encrypted files and reject non-vault files early.

### Format Version (1 byte)
Currently `0x01`. Incremented when breaking changes are made to the format.

### Algorithm ID (1 byte)
| Value | Algorithm |
|---|---|
| `0x01` | AES-256-GCM |
| `0x02` | Reserved (ChaCha20-Poly1305) |

### KDF ID (1 byte)
| Value | KDF |
|---|---|
| `0x01` | PBKDF2-HMAC-SHA256 (600,000 iterations) |
| `0x02` | Reserved (Argon2id) |

### Flags (1 byte)
Reserved for future use. Currently `0x00`.

### Multi-byte Integer Encoding
All `uint16` fields are stored in **little-endian** byte order.

### Salt
Random bytes generated by `RAND_bytes()`. Used as input to the KDF along with the password. Not secret — stored in plaintext in the header.

### Nonce/IV
Random bytes generated by `RAND_bytes()`. Used as the initialization vector for AES-256-GCM. Must be unique per encryption with the same key.

### Original Filename
The basename of the original file (without directory path), stored as UTF-8. Used by the `info` command and optionally for output path generation during decryption.

### Ciphertext
The AES-256-GCM encrypted content of the original file. Same size as the original plaintext (GCM is a stream cipher mode).

### Authentication Tag
16-byte GCM authentication tag. Covers all ciphertext. Verified during decryption — if verification fails, no output is produced.

## Example: Hex Dump of a .vault File Header

```
00000000: 46 56 41 55 4c 54 00 00  01 01 01 00 10 00 0c 00  FVAULT..........
00000010: 10 00 08 00 a3 7b 4e 91  c2 d8 f0 12 3a 8b 6c e5  .....{N.....:.l.
00000020: 88 41 2d 73 b9 f7 c3 5a  e1 0d 94 68 27 ab 4c 82  .A-s...Z...h'.L.
00000030: 4b 69 6e 67 2e 74 78 74                            King.txt
```

Breakdown:
- `46564155 4c540000` → Magic "FVAULT\0\0"
- `01` → Version 1
- `01` → AES-256-GCM
- `01` → PBKDF2-HMAC-SHA256
- `00` → Flags (none)
- `1000` → Salt length = 16 (LE)
- `0c00` → Nonce length = 12 (LE)
- `1000` → Tag length = 16 (LE)
- `0800` → Filename length = 8 (LE)
- Next 16 bytes → Salt
- Next 12 bytes → Nonce
- Next 8 bytes → "King.txt"
- Remaining → Ciphertext + 16-byte tag at end
